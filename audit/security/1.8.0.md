# Security review — 1.8.0

Free plugin is distributed on WordPress.org; Pro is a commercial addon sold
directly (not wp.org-hosted). Reviewed together since they ship as a pair.

## Plugin Check on the built distribution zips

Ran `wp plugin check` against the actual `dist/*.zip` contents (extracted to a
temp slug), not the dev source tree, per the release standard — source-tree-only
scans pass dev scripts/hidden files that never ship and miss nothing packaging
would introduce.

**Free (`product-roadmap-1.8.0.zip`)** — 0 real errors. The only ERROR-severity
rows returned (733, all `WordPress.WP.I18n.TextDomainMismatch`) are an artifact
of the temp check-slug directory name (`product-roadmap-distcheck`) not matching
the plugin's real text domain (`product-roadmap`) — every `__()`/`_e()` call in
the plugin trips it identically. The plugin's actual text domain is correct for
its real wp.org slug. No genuine errors. WARNING-level output scanned for the
highest-risk categories (eval, unserialize, `nopriv`, `__return_true` permission
callbacks, missing direct-file-access guards, unfiltered file operations, SSRF-
shaped remote requests, upload filetype checks) — zero hits.

**Pro (`roadmap-pro-addon-1.8.0.zip`)** — 2 ERROR-severity findings, both
scanner-visible-but-safe:
- `WordPress.WP.I18n.TextDomainMismatch` — same check-slug-naming artifact as
  Free, not a real defect.
- `plugin_header_invalid_license` — Plugin Check requires a GPL-compatible
  license header for wp.org hosting. Pro is deliberately `License: Commercial`
  (matches `readme.txt`, both now consistent — see fix below) and is not
  distributed via wp.org, so this check's premise doesn't apply. Accepted.

Same WARNING-level security-category scan run on Pro: zero hits.

### Fixed this cycle
- Plugin header (`roadmap-pro-addon.php`) declared `License: GPL v2 or later`
  while `readme.txt` declared `License: Commercial` — a genuine inconsistency
  (likely copied from the Free plugin's template). Header now matches
  `readme.txt`: `License: Commercial`, `License URI: https://wbcomdesigns.com/license/`.

## Gate A — static analysis

## G2 — authorisation spot-checks (from this release cycle's fixes, re-verified live)

- **Analytics REST routes** (`/analytics`, `/overview`, `/trends`,
  `/popular-items`, `/recent-activity`, `/charts`): `Roadmap_Pro_Api::can_view_analytics()`
  checked `edit_posts` (held by every Contributor) instead of
  `roadmap_view_analytics`. Fixed to route through
  `Roadmap_Permissions::can_view_analytics()`. Verified live via real
  logout/login: Contributor -> 403, Administrator (holds the capability) -> 200.
- **CSV export gate** (`roadmap-pro-addon.php` `handle_csv_export_request()`):
  same shape, an `edit_posts` OR-fallback let any Contributor+ role bypass
  `roadmap_view_analytics`. Fixed earlier this cycle (`e18b0db`).
- **Member ownership** (`class-roadmap-permissions.php` `can_edit_item()` /
  `can_delete_item()`): `roadmap_item` is `capability_type => 'post'` with no
  `map_meta_cap` override, so WordPress's native edit/delete-post meta-cap
  required base `edit_posts` before ownership was even checked — a Subscriber
  could never pass regardless of `roadmap_edit_own_items`. Fixed to check the
  plugin's own capability + ownership directly. Verified live via REST as two
  distinct subscriber personas: owner can edit/delete their own item,
  non-owner cannot.
- **CSV formula injection**: leading `=`/`+`/`-`/`@` in exported fields is
  neutralized (`roadmap_pro_csv_row()`), wired into both export paths.

No unauthorized-read or unauthorized-write findings remain open from this
cycle's G2 checks.

## Gate F — action wiring

AJAX handler cross-check, both plugins: all registered `wp_ajax_` handlers
trace to a real caller (JS `$.post`, or a direct `<a href>` for the
CSV-download link, which uses the AJAX endpoint as a plain GET). No orphaned
selectors or broken AJAX found; the 2 pre-existing "possibly dead" Free
handlers were already flagged non-blocking by the contract audit.

## What blocks vs what doesn't

Nothing from this review blocks 1.8.0. The two accepted Pro findings above are
scanner-visible-but-safe for a non-wp.org commercial product, documented here
so a future reviewer (human or AI) doesn't re-litigate them.
