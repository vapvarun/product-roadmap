## 1. Read this first: the one blocker (now fixed, needs a QA re-pass)

**[Bugs #10326920444](https://3.basecamp.com/5798509/buckets/43291050/card_tables/cards/10326920444) — changelog slug bug.** ~~Publishing a changelog entry in the block editor under a non-default product still wrote a `general-` slug prefix instead of `{product}-v{version}`.~~

- **Where the file actually lives:** `product-roadmap/includes/class-roadmap-changelog.php` (Free, not Pro — the original triage cited the wrong repo).
- **Root cause:** `auto_generate_slug()` runs on `wp_insert_post_data`, which fires *before* the block editor's REST request attaches the `roadmap_product` term or saves the version meta (both happen later in the same request). The first save saw "no product yet" and fell back to `general-{title}`, which then never got corrected on later saves.
- **Fix:** `eab838d` — added `fix_slug_after_rest_terms()` on `rest_after_insert_roadmap_changelog` (fires after REST finishes attaching terms/meta), which corrects a lingering `general-` prefix once the real product is known. Purely additive; the classic-editor path is untouched.
- **Verified live**, twice, with different products (`beta-suite-v9-9-9`, `gamma-api-v3-1-4`) — reproduced the bug with the old code first, then confirmed the fix. Fix note posted on the card, moved back to **Ready for Testing**.
- **Next:** one more `/wp-card-qa` pass on that card (ideally by someone other than whoever wrote the fix) to close it out, then the release is fully unblocked.

## 7. How this was verified

- Every card above was reproduced independently in the browser as the role(s) it names — not taken on the fix note's word — per `/wp-card-qa`.
- Card #1 (the white-screen/version-compat card) needed a real version swap: verified using **git worktrees** at tag `v1.7.1` in throwaway plugin folders (`product-roadmap-old171`, `roadmap-pro-addon-old171`, `product-roadmap-zip180`), never by touching the live checkouts' branch. All worktrees removed, both repos confirmed clean on `1.8.0` afterward, active-plugin state and vote counts confirmed unchanged. Reuse this pattern if that card ever needs re-verifying.
- Combo `wp-plugin-smoke` walk: zero new debug.log lines across the full run.
- Contract-audit (`wp-contract-audit`): 0 errors.

**Lesson worth carrying:** don't run multiple browser-driven QA testers in parallel against the same site — a 3-way parallel attempt earlier in this pass hit a real Playwright MCP session-sharing bug (one tester saw another's logged-in identity mid-flow, a click landed on the wrong element). Caught before anything bad was posted to Basecamp, but the fix was to serialize, not to paper over it. If this comes up again, verify session isolation first or just don't parallelize browser work against one live site.
