# Product Roadmap 1.7.0 — Browser Test Checklist (Tier 1)

**Rule:** every workstream with a frontend/template/JS change is browser-verified (Playwright MCP) BEFORE its task is marked done — per-item, not batched at the end. Check hover/focus/visited on `<a>` buttons. Screenshots → `~/Documents/work-artifacts/screenshots/2026-07/`.

**Test env:** `http://roadmap.local` · autologin `?autologin=1` (admin) · seed = 5 products / 1000 items / 4100 votes (meta `_seeded=1`). Also run a **clean-install pass** (fresh activate, no seed) before release.
**Viewports:** desktop 1440 · tablet 768 · mobile **390** (all three for any layout change). **Themes:** light + dark. **RTL:** spot-check one flow.
**Roles:** admin · editor/author · logged-in subscriber · **logged-out guest**.

Legend: ☐ todo · marks the workstream it gates.

---

## Pre-flight (every session)
- ☐ No PHP notices/warnings in `wp-content/debug.log` on load of board + admin.
- ☐ Browser console: 0 errors on board, single item, admin analytics, admin settings.
- ☐ Both plugins active; Pro license shows valid.

## BT-CORE — essential loop (regression guard, run every session)
- ☐ Board renders items in status columns (desktop/tablet/390).
- ☐ Vote as logged-in → count increments, persists on reload, cannot double-vote.
- ☐ Vote as guest (if guest voting on) → IP-deduped, count increments.
- ☐ Submit suggestion (logged-in) → success msg, appears pending in admin.
- ☐ Submit guest suggestion → requires name+email, success, pending in admin.
- ☐ Add comment on an item → appears, admin email fires.
- ☐ Changelog page renders entries (seed ≥1 changelog).

## BT-ANALYTICS — W1 + W2  (the flagship fix)
- ☐ Before fix: confirm `wp_*` analytics/events empty after a vote (baseline).
- ☐ After: vote → analytics events table gains a row (vote event).
- ☐ Change item status → status-change event recorded.
- ☐ View a single item → view event recorded (`roadmap_item_viewed` fires).
- ☐ Admin → Analytics dashboard: votes chart, popular items, status distribution show REAL non-zero data.
- ☐ Period switch (7/30/90/year) changes the numbers.
- ☐ Console/network: `/analytics/track` returns 200 and payload keys match server.

## BT-FILTERS — W1 + W11  (advanced filtering)
- ☐ Apply priority filter on board → list narrows correctly.
- ☐ Apply progress/date/assignee filter → narrows (proves `roadmap_api_query_args` fires).
- ☐ Period/type dropdowns list the SAME options the API accepts (enum parity).
- ☐ Save a filter preset → reload → preset reapplies.

## BT-MULTIPRODUCT — W3
- ☐ `[roadmap product="alpha-app"]` shows only alpha-app items; `beta-suite` shows only its items.
- ☐ Product switcher changes the board without full reload.
- ☐ Global view: `product=all` (or documented behavior) shows across products — or confirm single-product-by-design is intentional.
- ☐ Assign an item to a product in admin → appears under that product on frontend.
- ☐ No "post type roadmap_product is not registered" notice anywhere (CPT collision resolved).

## BT-TIMELINE / BT-EXPORT — W3 + W7
- ☐ Pro timeline view renders items chronologically for a selected product (not empty).
- ☐ CSV export for a product downloads with the correct product's rows only.
- ☐ Export at scale (product with 200 items): completes, no fatal/timeout, memory sane.

## BT-PAGINATION — W5
- ☐ Product with >100 items (alpha-app=200): board shows a pager/load-more and can reach items 101–200.
- ☐ "Showing X of Y" indicator correct.
- ☐ `per_page` above the max is clamped (network check); response has `X-WP-Total`.
- ☐ Pager keyboard-reachable + focus ring; works at 390px.

## BT-SCALE-QUERIES — W6 + W7  (Query Monitor)
- ☐ Board load (200-item product): no query full-scanning `wp_roadmap_votes` (index used).
- ☐ Admin analytics load: total query count bounded (no COUNT-in-loop / no `-1` load-all).
- ☐ Products list (5 products): single grouped count query, not one-per-product.
- ☐ Page/query time on 1000-item dataset within budget (record ms).

## BT-SECURITY — W8
- ☐ Pro REST approve/reject/merge → 401/403 for logged-out and for a subscriber.
- ☐ guest-suggest → allowed but rate-limited (spam a few → throttled).
- ☐ Vote nopriv path requires valid nonce (tamper → rejected).
- ☐ Settings save → nonce + capability enforced; invalid input sanitized (try `<script>`).

## BT-SETTINGS-TAB — W1
- ☐ Pro adds its settings tab/section (proves `roadmap_settings_*`/`roadmap_render_*` fire).
- ☐ Save a Pro setting → persists → is READ on the frontend (no half-wired setting).

## BT-A11Y — W10
- ☐ All form inputs have labels (axe/manual); no input without a name.
- ☐ Keyboard-only: tab through board + forms, visible focus ring everywhere.
- ☐ No native `alert()`/`confirm()` — in-UI notice/modal instead.
- ☐ Dark mode + RTL spot-check on board + settings.

## BT-UNINSTALL — W9

## BT-I18N — W9
